## 修复 SUATCatManager.exe 无法使用

- 现象：双击 exe 打开的窗口空白/无法使用。
- 根因：近期把数据文件重构进 `data/` 目录时，误删了 `app_manager.html`（管理器前端）。而 `app.py` 的内置 HTTP 服务器仍在 `BASE_DIR` 根目录提供 `/app_manager.html`，导致 exe 运行时该页面 404。
- 关键点：`app_manager.html` 是通过磁盘上的 HTTP 服务器提供的，**并未被 PyInstaller 打进 exe**（build.py 没有 --add-data 该 html）。因此只需把文件放回项目根目录即可修复现有 exe，**无需重新打包**。
- 该前端所有数据均通过 pywebview `js_api`（`api.*`）获取，不直接 fetch json，因此与新的 `data/` 结构完全兼容，无需改内部路径；它只静态引用根目录的 `marked.min.js`（存在）。
- 修复：恢复 `app_manager.html` 到项目根目录（79993 字节）。
- 验证：用与 app.py 相同逻辑的临时 HTTP 服务器测试，`/app_manager.html`、`/marked.min.js`、`/data/cats.json`、`/index.html` 均返回 200。

## 让 exe 真正打进前端 + 修复 conda(WZT)打包的 _ssl 报错

- 用户诉求：删 exe → 用 conda `WZT` 环境重新 `build.py` 打包 → 双击能开。
- 改造1（app.py）：前端静态文件 `app_manager.html` / `marked.min.js` 改为优先从打包资源目录（`sys._MEIPASS`）读取，数据仍从磁盘读。这样即使 exe 同目录缺 html 也能开。
- 改造2（build.py）：新增 `collect_conda_dlls()`，检测到存在 `<sys.prefix>/Library/bin`（conda 专属，venv 没有）时，把里面所有 `.dll`（含 `libssl-3-x64.dll`、`libcrypto-3-x64.dll`、`libopenblas` 等）通过 `--add-binary ...;.` 打进 exe。
- 根因（conda 报 `ImportError: DLL load failed while importing _ssl`，venv 不报）：conda 把 OpenSSL 运行时 DLL 放在 `<env>/Library/bin`，而 `--collect-all ssl` 只带 `_ssl.pyd`，漏掉真正需要的 OpenSSL DLL；标准 CPython 的 OpenSSL DLL 挨着 python DLL，PyInstaller 会自动带上。
- 验证：用 WZT(Python 3.10.20) 跑 `build.py`，日志显示「conda 运行时 DLL: 69 个」，产出 `SUATCatManager.exe`(33MB)；运行后 `_MEI*` 临时目录内含 `libssl-3-x64.dll`（共 71 个 dll），确认 `_ssl` 已修复。
- 约定：本项目打包环境优先用 conda `WZT`（C:\Users\ADMIN\.conda\envs\WZT）；build.py 对 conda/venv 都已兼容。
